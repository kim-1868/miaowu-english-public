# 小说工厂批次测试：公共/私人边界（2026-11-08）

## 目的
将**不含真实书稿和敏感信息**的批次结构回归放在公共 GitHub Actions 中执行，降低私人仓库的日常测试频率。只是测试归属调整，不改变网站部署来源。

## 公共自动测试（已补充合成用例）
- `scripts/story-batch-contract.mjs` + `tests/story-batch-contract.test.mjs`：五等级枚举、书籍身份、章节总数/已写章号、断点续写重复章号、不合法章号、同等级新教学义项预留碰撞、跨等级相同义项不误判、同词不同义项区别、旧词和新词重叠、含标注段落的算术密度、标注 wordId 引用。
- 只使用人工虚构的三个项目代号和少量英文例词，不涉及用户的六本小说题材、实际词表、书籍 ID、教学文本、用户、订单、D1、密钥或 GitHub 私有历史。
- 仍用现有 `public-guard.yml` 中 `npm run check`、`npm test` 自动触发，公共 Actions 不使用私人额度；没有必要为此增加公开 Chromium 屏幕检查。
- 这些检查只是**结构/数量一致性**，绝不能证明一篇小说内容自然、词义/IPA 正确或可发布。

## 私人内容及真实发布门禁（必须保留）
- 原创小说正文、真实词卡、考试候选词库、审核表、订单和登录态：仅在私人资料库/私人业务环境。
- 50/251 等真实内容数据的教学终审、音标来源、同义项 studyKey 与旧学习状态核对：私人受控离线检查或必要的私人 Gate。
- 上架前测试 D1 的真实导入、Paid 墙、发音、记忆藏书票、剧情回声、权益、回滚：私人隔离测试，不可能由公共的虚构样本替代。
- 上线仍需用户明确批准的发布流程；公共测试通过不会导致任何自动上架。
